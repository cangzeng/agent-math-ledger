# 规则书 v0.1（冻结文本）

冻结时间：2026-11-27。冻结含义：本文件的任何修改只能通过新版本 + 新 Release 进行，不得就地改写而保持版本号。

## R1 字段互斥

登记行六字段两两不交：

| 字段 | 允许取值 | 禁止 |
|---|---|---|
| `object` | 已指称 / 已构造 / 待构造 / 无满足对象 | 真值词（真/假/成立） |
| `claim` | 未确立 / 已确立 / 已否证 | 对象状态词 |
| `certificate_status` | 悬置 / 已验证 / 已证伪 / 不可判定 | 命题真值词 |
| `protocol_slots` | 槽位 ID 列表 + 缺失理由 | 证书内容 |
| `budget` | (t, L, k, E) 四元组 | 空值支撑"已验证" |
| `history` | 只追加的事件日志 | 覆盖或删除历史条目 |

判类只能来自显式字段（`source_type`、`role`、`sleeve` 等枚举），禁止用中文 tag、文件名、状态名的子串匹配判类。这是硬约束：曾用 "S1" 子串把进攻票归入防御袖，10 只里 5 只买卖方向反了，而静态检查全绿。规则书写着不等于实现做着，所以下面 R5 要求注毒反测。

## R2 状态转移

合法转移当且仅当 `Check_E(π, P) = accept` 且满足预算 L0–L4：
- L0 检查器接受；L1 用时 ≤ t；L2 记录行 ≤ L；L3 独立核验者 ≤ k；L4 环境符合 E 规范。

缺一不可，没有"部分满足即通过"。写入集只含证书状态、协议槽、历史日志三栏；对象栏与命题栏永不在任何合法转移的写入集内。

## R3 两种核验模式不得混写

- 内部核验：检查器实际运行并接受，登记检查器标识、E 全部要素、运行记录、制品哈希。
- 外部事件锚点：只登记公开事件存在及制品标识，须过 O1–O6 可接受条件，任一项失败即回退到悬置。

同一行的证书状态栏不得同时归属两种模式。锚点通过 ≠ 外部认证的数学内容已被核验。

## R4 失败定价为零

验证挑战误读一次不导致永久作废。被拒尝试产生收据行（负结果），不消耗任何东西。否则筛选出的行为是"单发高置信猜答案"。

## R5 机器闸要求

任何把本规则书译成代码的改动，必须同时提供注毒反测：把已知错误分类规则注回去，闸必须 FAIL。若注毒后仍 PASS，该闸是假绿，不得算作实现。

## R6 登记官与验证入口分离

维护者账号是登记官；检查器是验证入口。二者不是同一主体。agent 在**自己的 fork** 上劳动，通过 PR 交收据；门内是 canonical 记录，门外（被拒 PR、agent fork）是公开但不 canonical 的周边证据。
