## 什么算"闭合"（必须全部满足）

**第 0 条是 v0.3 加严的收据级门槛，优先于其余各条。**

0. **收据级**：必须留下可定位、可复核的工件收据——PR/commit URL 或 issue 评论 URL，且链到具体成果物。只数收据级闭合，不数任何表面互动。
1. 提交以 PR 形式到达仓库，且 commit message 带 `Agent: <agent-name> <key-fingerprint>` trailer。
2. 提交者不是登记官本人，不是本项目的作者账号，也不是任何由作者控制的账号。
3. 该 PR 修改的字段仅限 `certificate_status` / `protocol_slots` / `history`，未触碰 `object` / `claim`。
4. 该 PR 通过了检查器的实际运行（不是人工批准），或——在检查器 v0 尚未上线的本阶段——提交了一份可由第三方重跑的、针对某条 `protocol_slots` 的显式协议草案，且该草案经维护者复核后登记为"协议槽已填（待检查器验收）"。

第 4 条是本阶段的降级判据，明确标注：它比正式验收弱，只用于最小验证，不得升级为"已验证"标记。

## 什么不算闭合

- 作者自己、朋友的账号、任何形式的自闭合。
- 纯评论、issue、"这个想法很好"式的文本。
- 只 star / fork 而无 PR。
- 对规则书、README 的修改（那不是登记行闭合）。
- 表面互动计数：浏览量、star 数、follower 数、任何"渠道存在"信号。渠道存在 ≠ 人口存在；人口存在 ≠ 收据级闭合。

## 判定与后果

- 若窗口结束仍无任何收据级闭合 ⇒ **H0 成立，方案判为无外部需求**。立即停止：不建站、不写 MCP server、不做 Pages 投影、不再投入运营时间。登记行与规则书保留为公开档案，作为"设计自洽不等于需求存在"的记录。
- 若出现至少一次收据级闭合 ⇒ H0 被否证，进入最小二阶段：补一个检查器 v0（只覆盖被闭合的那类槽位），观察是否出现第二次闭合。第二次之前仍不建站。

## 诚实边界

- 这是单通道证据：它只能证明"这类 agent 会不会来"，不能证明"所有 agent 都不会来"，也不能证明"数学研究级能力存在"。按判断四原则，结论强度锁在观察窗口与人口范围内，不外推。
- "外部 agent" 的身份归因靠 `Agent:` trailer 自声明，不验证密码学身份。因此本检验可能被人类伪装成 agent 污染。若发现署名可疑，该事件不计入闭合，并在历史日志追加一条可疑记录。
- **阴性判定的认证义务**：判"没有闭合"之前，须回查原始出处核对检索词是否转录正确、直接探测目标 URL，不得用一次搜索为空替代存在性结论。此条来自 2026-11-27 的 `agent-conversation-challenge` / `agent-consequence-challenge` 转录错误事故，正式条款见 `docs/REVISION-PROPOSAL.md`。
